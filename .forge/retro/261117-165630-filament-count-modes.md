# 2026-11-17 — 필라멘트 개수별 동작: 1개 높이만 · 2개 흑백 층(색 선택) · 3~4개 색 영역 + 톤 높이

## Plan vs actual
- 계획대로 진행된 것: 색 영역 코어(Lab 최근접 분류 + `processImage` 와 같은 톤 높이), 층 모드 색 선택(기본 출력은 배포본과 바이트 동일), UI 모델, 워커·뷰어, 위저드 패널, 샘플. 테스트 88개, 브라우저 UAT, 사용자의 Bambu Studio 확인까지 통과.
- 불일치:
  - 실행 후 "3개 이상은 왜 양면인가" 지적으로 파트 구조를 바꿨다. 색 파트가 바닥부터 통째라 그림이 바닥면에도 나오고 베이스 구간에서도 매 레이어 필라멘트가 바뀌었다. 슬롯 1 색 베이스 판 + 나머지 색은 베이스 윗면부터 + 모든 셀 1레이어 추가로 수정(ADR Amendment 3).
  - 이 작업에 이르기까지 의도 해석이 네 번 어긋났다: K색 높이 구간 층 → 채도 기준 색 그룹 + 베이스 슬롯 → 층 쌓기 순서 위저드 → 평평한 색 영역. 모두 `.forge/dropped/` 와 git stash 에 남아 있다. 사용자가 실제 화면 스크린샷(분홍 볼에 화살표)을 보여 준 뒤에야 의도가 분명해졌다.

## Learnings
- 다음에 다르게 할 것:
  - 출력 모양이 핵심인 요청은 코어만 만들고 말로 설명하지 말고, 첫 반복부터 화면(UI)에 연결해 사용자가 직접 보게 한다. 이번에는 세 번의 시도가 UI 없이 코어와 설명만으로 진행되어 사용자가 결과를 볼 수 없었다.
  - "색", "층", "그룹" 같은 말은 해석이 여러 갈래라, 계획 전에 사용자의 실제 이미지로 "이 부분이 이 색으로 나오는가"를 그림으로 확인받는다(fg-showme 같은 시각 비교 또는 합성 미리보기).
  - 다중 재료 모델은 첫 설계 때 "바닥면에 무엇이 보이는가"와 "어느 레이어에서 필라멘트가 바뀌는가"를 함께 점검한다.
- 확인된 것(유지): 기본값 회귀는 HEAD 와 3MF 엔트리 sha256 비교로 잡는 방식이 리팩터링 중 매번 유효했다.
